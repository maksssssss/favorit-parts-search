# Шпаргалка по коду (для обсуждения на собеседовании)

## Поток данных за 30 секунд
1. `SearchForm` вызывает `onSearch(number)` → `App` диспатчит thunk `loadBrands(number)`.
2. `createAsyncThunk` вызывает `api.fetchBrands` → `fetch('/api?key=…&number=…')`.
3. Slice обрабатывает три action-а: `pending` (сброс состояния, статус `loading`), `fulfilled` (бренды в стейт), `rejected` (текст ошибки).
4. `App` читает стейт через `useSelector` и рисует лоадер / ошибку / пустой результат / `BrandList`.
5. Клик по бренду → `loadOffers({ number, brand })` → запрос с `analogues=on` → `OffersTable`.

## Решения и «почему»
- **Redux Toolkit, а не чистый Redux:** `createSlice` и `createAsyncThunk` убирают бойлерплейт; ТЗ требует Redux, RTK — его официальный способ.
- **Прокси `/api`:** API работает только по HTTP. Страница на HTTPS не может ходить на HTTP (mixed content). Поэтому браузер ходит на свой `/api`, а Vite (dev) или rewrite Vercel (prod) пересылает запрос.
- **Ключ в клиенте:** это публичный демо-ключ из документации. В реальном проекте ключ держат на сервере/прокси, а не в бандле.
- **Ошибки API приходят как `{"error": "..."}`**, иногда с HTTP 200, иногда с 403. Поэтому тело читается всегда, а текст из `error` приоритетнее статуса.
- **Бренды = уникальные `brand` из `goods`:** отдельного эндпоинта «список производителей» нет, список выводится из ответа по артикулу.
- **Аналоги:** в ответе они лежат в `goods[].analogues[]`; `flatMap` собирает основную позицию и аналоги в один плоский список.
- **Остаток** берётся из `count` (общий по всем складам); детализация по складам в ТЗ не требовалась.

## Подводные камни, которые уже учтены
- **Гонка запросов:** в slice хранится `requestId` последнего запроса каждого этапа; ответ, пришедший не от последнего запроса, игнорируется. Есть тест.
- **Новый поиск сбрасывает этап 2** (`pending` возвращает `initialState`).
- **Дубли `key`:** `id = goodsID-index`, потому что `goodsID` может повторяться.
- **Цена 0 или её отсутствие** показывается как «—».

## Что можно улучшить (честно)
- Хранить запрос и бренд в URL (ссылкой можно поделиться, работает «Назад»).
- Реальная отмена запросов через `AbortController` (сейчас устаревшие ответы просто игнорируются).
- Детализация по складам и срокам отгрузки (`warehouses[].shipmentDate`), сортировка и фильтр по цене/наличию.
- Ключ API вынести на серверный прокси (Vercel Function).
- Разбить `App.jsx` на секции «Бренды» и «Предложения», добавить компонентные тесты.

## Вопросы, которые могут задать
- *Что делает `createAsyncThunk` и какие action-ы диспатчит?* — `pending`/`fulfilled`/`rejected`, с `meta.requestId` и `meta.arg`.
- *Как бы вы обработали отмену запроса?* — `signal` из thunk-а передать в `fetch`, `AbortController`.
- *Почему не хранить `offers` в локальном state?* — требование Redux и общий стейт двух этапов; повторный запрос/ретрай читает `query` из стора.
- *Где слабые места?* — публичный ключ и лимит запросов (403), отсутствие URL-состояния.
